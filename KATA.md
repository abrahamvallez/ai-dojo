# Kata · development

Tenéis una app que ya funciona (Dojo Paint, mirad el `README.md`) y los cambios que hay que hacerle, ya especificados en `openspec/changes/`. El comportamiento actual está en `openspec/specs/`.

No tenéis que pensar en qué construir ni describirlo: está hecho. Lo interesante es **cómo preparáis y ejecutáis ese trabajo con agentes**: qué contexto les dais, cómo dividís el trabajo, qué modo de ejecución elegís y cómo comprobáis el resultado.

## Reglas

1. Trabajad en parejas, con un único repo por pareja.
2. Cada persona usa las herramientas con las que trabaja a diario y las usa como lo haría un martes cualquiera. No hay una forma correcta de trabajar con IA, y de eso va el ejercicio.
3. No hay maestro ni alumno. Si la otra persona hace algo que vosotros no hacéis, preguntad y probadlo.
4. Pensad en voz alta: qué pedís, por qué lo pedís y qué comprobáis antes de aceptar lo que genera la IA.
5. Cambiad quién lleva el teclado cada 20 minutos aproximadamente.
6. Elegid cuántos cambios abarcáis, en qué orden y con qué calidad. Acabar menos y mejor es una decisión tan válida como acabar más.
7. Haced commits como en el trabajo.

## Tiempo

Entre 60 y 75 minutos. Después, retro en común.

## Para empezar

```bash
npm install
npm run dev
```
